# Scope and verification

PI/OpenAI. Reader: a research agent adapting a judge, without this conversation.

User requirements (spelling corrected): “my good defaults and guidance for LLM-as-judge”; “composable and readable and annotated with why we have this default”; “make sure you redirect the gist and update links to this repo”; “can just be public”.

The repository is the single maintained implementation. Core includes durable execution, explicit numerical judgments, counterbalanced views, a broad unscored vent and full traces. Optional diagnostics/interviews are normal importable functions, not a plugin framework. Main uses are pair comparisons, multi-rubric labeling and debugging measurement itself. Hierarchical routing is not silently substituted for independent rubric coverage.

Verification must distinguish functional plumbing from model validity: maintained HTTP/Inspect regression paths; an installed-package smoke; cache replay; source-backed hierarchy semantics; a fresh agent executing the documented offline workflow; an independent code reviewer; and a design oracle checking the defaults against the user's goals. No dataset API spending is authorized for these checks. No private dataset traces, credentials or generated run logs enter the public repository.

Security: package-age hold stays at eight days; uv.lock is committed and installs use --locked. Build metadata explicitly maps distribution wassname-llm-judge to import module llm_judge. An initial install failed on the default module-name assumption; corrected using the official uv build-backend documentation, without changing the release-age hold.

Source lineage is recorded in source_provenance.json. The previous gist and local runners retain history; the gist will become a short redirect only after the public repo has a tested commit/tag. Local ML-debug guide links will point at the new repository.
